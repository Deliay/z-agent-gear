# 工作流 Worktree 节点会话启动失败修复

**功能名称**: 工作流 Worktree 节点会话启动失败修复
**PRD 版本**: v1.0
**创建日期**: 2026-08-29
**作者**: Kimi

## 一、背景与目标

### 1.1 背景

工作流级 Worktree（见 [[20260821-workflow-optimization]]）上线后，用户在实例化工作流时可勾选「为工作流创建 Worktree」，让实例内各 AI 节点会话统一在专属 Worktree 中工作，实现整流程的工作内容隔离。

实际使用中发现：**勾选「为工作流创建 Worktree」创建工作流后，进入工作流节点、流转到 AI 节点时，节点会话启动失败，报错「existingWorktreePath does not belong to this workspace」**。节点无法拉起会话，整个工作流被阻断，用户只能放弃 Worktree 隔离选项重新创建实例。

### 1.2 目标

1. **消除启动报错**：勾选「为工作流创建 Worktree」的工作流实例，其 AI 节点会话能够正常启动，工作目录为工作流专属 Worktree。
2. **安全性不回退**：Worktree 路径归属校验仍然有效，非法/越权路径依旧被拒绝。
3. **规则一致**：平台内所有涉及 Worktree 路径归属判断的入口，对同一路径给出一致结论。

### 1.3 成功标准

- 在 Git 工作区勾选「为工作流创建 Worktree」实例化工作流，流转到 AI 节点时会话正常启动，不再出现「existingWorktreePath does not belong to this workspace」报错。
- 节点会话的工作目录确认为该工作流实例的专属 Worktree 目录。
- 使用平台默认的 Worktree 存储位置或用户自定义的存储位置，上述流程均正常。
- 传入不属于该工作区的 Worktree 路径时，系统仍拒绝并提示，防护能力不削弱。

## 二、用户分析

### 2.1 目标用户

- **个人开发者**：使用工作流完成需求开发，依赖工作流级 Worktree 做工作内容隔离。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点 |
|------|----------|------|------|
| 创建带 Worktree 隔离的工作流 | 开发者 | 各节点会话在隔离目录中工作 | 流转到 AI 节点即报错，工作流阻断 |
| 复用既有 Worktree 启动会话 | 开发者 | 在已有 Worktree 上继续工作 | 合法路径被误判为「不属于此工作区」 |

## 三、功能需求

### 3.1 功能概述

修复工作流 Worktree 路径的归属校验误判：平台为工作流创建的专属 Worktree，在 AI 节点会话启动时应被正确识别为属于该工作区，会话正常拉起；同时保持对非法路径的拒绝能力。

### 3.2 功能列表

#### 功能点 1：工作流 Worktree 节点会话正常启动

- **描述**: 勾选「为工作流创建 Worktree」的工作流实例，流转到未单独启用「初始化新 Worktree」的 AI 节点时，节点会话直接以工作流 Worktree 为工作目录启动，全程无报错。已单独启用「初始化新 Worktree」的节点行为维持现状。
- **用户价值**: 工作流级 Worktree 隔离能力真正可用，无需绕行。
- **验收标准**:
  - [ ] 默认 Worktree 存储位置下，带工作流 Worktree 的实例流转到 AI 节点，会话正常启动且无报错。
  - [ ] 自定义 Worktree 存储位置下，上述流程同样正常。
  - [ ] 节点会话的工作目录为工作流专属 Worktree 目录。
  - [ ] 单独启用「初始化新 Worktree」的节点仍创建自己的 Worktree，行为与现状一致。

#### 功能点 2：Worktree 路径归属校验规则一致

- **描述**: 平台内所有对「Worktree 路径是否属于某工作区」的判断（会话启动、Worktree 列表与删除等入口）采用一致的口径，同一路径在各入口结论一致。
- **用户价值**: 不会出现「列表里能看到的 Worktree，启动会话时却被拒绝」这类自相矛盾的体验。
- **验收标准**:
  - [ ] 平台创建并展示的 Worktree，在各入口均能被识别为属于对应工作区。
  - [ ] 不属于该工作区的路径，在各入口均被一致拒绝。

### 3.3 用户操作流程

```mermaid
flowchart LR
    A[实例化工作流<br/>勾选为工作流创建 Worktree] --> B[平台创建工作流专属 Worktree]
    B --> C[流转到 AI 节点]
    C --> D[节点会话以工作流 Worktree<br/>为工作目录正常启动]
    D --> E[工作流继续流转]
```

### 3.4 页面/界面描述

无新增页面与界面变更。修复后，原先报错的节点会话启动流程静默恢复正常，用户无感知。

### 3.5 异常与边界情况

| 场景 | 预期行为 |
|------|----------|
| 传入不属于该工作区的 Worktree 路径 | 拒绝并明确提示，防护行为不变 |
| 工作区非 Git 项目 | 维持现状：无法创建工作流 Worktree，实例化时给出说明 |
| 工作流 Worktree 已被外部删除 | 维持现有「会话启动失败 → 节点标记失败 → 人工介入」流程 |
| 节点单独启用「初始化新 Worktree」 | 维持现状：创建节点级 Worktree，不复用工作流 Worktree |

## 四、非功能需求

- **安全性**: 路径归属校验的防护强度不回退，越权路径必须被拒绝。
- **兼容性**: 修复不影响未勾选「为工作流创建 Worktree」的实例，也不影响普通会话与节点级 Worktree 会话。
- **可回归性**: 修复需覆盖自动化测试，防止后续对 Worktree 路径处理的改动再次引入同类误判。

## 五、依赖与约束

- 依赖现有工作流级 Worktree 能力（[[20260821-workflow-optimization]]）。
- 不改变 Worktree 的存储位置规则与用户配置方式。
