# question 工具多选题呈现修复

**功能名称**: ACP 问询（question 工具）多选题呈现与作答
**PRD 版本**: v1.0
**创建日期**: 2026-11-04
**作者**: ZeroAsh

## 背景与目标

### 1.1 背景

Agent 在会话中可以通过「问询」主动向用户提问（单选、多选、自由填写等题型），用户在弹窗中作答后答案回传 Agent 继续执行。当前单选题已能以单选组正确呈现，但**多选题在前端被错误地呈现为一个纯文本输入框**：用户看不到可勾选的选项列表，只能手动输入答案文本，既不知道有哪些选项、也容易输入与选项不一致的内容（GitHub Issue Deliay/z-agent-gear#445）。

### 1.2 目标

- Agent 发起多选问询时，前端以「多选勾选组」正确呈现全部选项，用户可逐一勾选/取消。
- 用户提交后，所选答案按问询协议以逗号拼接为一段文本回传给 Agent，Agent 获得与现状兼容的答案形态。
- 单选题、自由填写、数字、开关等其他题型的既有呈现与提交行为不受影响。

### 1.3 成功标准

- 多选问询弹出后展示为勾选列表，而不再是文本输入框。
- 用户可勾选一个或多个选项并提交；Agent 收到的该题答案为所选选项按逗号拼接的文本（例如 `自动跑测试,生成文档`）。
- 多选必答题未选择任何选项时不可提交，并提示用户补全。
- 单选题等其他题型的呈现与作答行为零回归。

## 用户分析

### 2.1 目标用户

- **前台用户**：在会话或工作流中回答 Agent 提问的用户，期望每种题型都有匹配的作答控件。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点 |
|--|--|--|--|
| Agent 一次提出多个问题，其中包含多选题 | 前台用户 | 直观地勾选多个答案 | 多选题只给文本框，看不到选项、只能凭记忆手打 |
| 多问一表中混合单选/多选/自定义填写 | 前台用户 | 每种题型都有匹配控件、一气呵成作答 | 多选退化为文本框，打断作答节奏且易答错 |

## 功能需求

### 3.1 功能概述

修复问询弹窗中多选题的呈现与提交：多选题渲染为勾选组展示全部选项；提交时把所选答案按逗号拼接为文本回传 Agent。

### 3.2 功能列表

| # | 功能 | 说明 |
|---|------|------|
| F1 | 多选题勾选组呈现 | 多选问询以勾选列表呈现全部选项（含选项说明，如有），可反复勾选/取消 |
| F2 | 逗号拼接提交 | 提交时把所选选项按逗号拼接为一段文本，作为该题答案回传 Agent |
| F3 | 必填校验 | 多选必答题至少选择一项才允许提交，否则阻止并提示 |
| F4 | 其他题型零回归 | 单选、自由填写、数字、开关等题型的呈现与提交行为保持现状 |

### 3.3 用户操作流程

```mermaid
flowchart LR
    A[Agent 发起多选问询] --> B[前端弹出问询窗口]
    B --> C[多选题以勾选组呈现]
    C --> D[用户勾选若干选项]
    D --> E{必答题均已作答?}
    E -- 否 --> D
    E -- 是 --> F[提交]
    F --> G[所选答案按逗号拼接<br/>回传 Agent 继续执行]
```

### 3.4 页面/界面描述

- 问询弹窗中，多选题展示题目标题、题目说明（如有）与一组勾选项；每项展示选项名称与选项说明（如有）。
- 勾选状态即时可见；弹窗在切换入口或重挂载后保留已勾选内容（沿用既有表单草稿行为）。
- 弹窗其余部分（题目消息、提交/拒绝/取消按钮、终态提示）与现状一致。

### 3.5 异常与边界情况

- 一个选项都不选且该题非必答：可提交，该题按未作答处理。
- 必答多选题一项未选：阻止提交并提示补全（与既有必填提示一致）。
- 问询已过期/已取消/已失效：弹窗展示对应终态并隐藏操作，不允许再提交（沿用既有行为）。
- 选项值本身包含逗号：按协议原样拼接，不做额外转义。

## 四、非功能需求

- 纯呈现层修复，不改变问询的发起、超时、终态与提醒口径；不新增用户操作步骤。
- 修复后移动端与桌面端的弹窗表现一致（沿用既有弹窗布局）。

## 五、依赖与约束

- 依赖既有 ACP 问询链路（Agent 发起 → 平台转发 → 前端弹窗 → 作答回传 Agent）。
- 答案回传形态需与 Agent（question 工具）的答案消费方式兼容：以逗号拼接的文本。
