# 用户界面优化

**功能名称**: 用户界面优化
**PRD 版本**: v3.0
**创建日期**: 2026-05-26
**作者**: opencode

## 背景与目标

### 1.1 背景

当前 Agent Web 的用户界面在多个场景下存在体验问题：

1. **操作无反馈**：关闭/删除会话等操作点击按钮后没有加载动画，用户不知道操作是否正在执行，容易重复点击
2. **输入框体验不佳**：模式/模型选择与输入框挤在同一行，输入框不能根据内容自动增高，长消息需要手动拖拽；切换页面后输入内容丢失
3. **消息展示混乱**：AI 返回的工具调用只显示最终状态，看不到各阶段的执行过程；可折叠的消息（如思考过程）需要用户手动一个个展开查看；用户发送的多条消息被合并在一起不易区分
4. **创建会话弹窗样式问题**：部分文字在某些主题下不可见，分支名称过长导致布局溢出，工作目录选择使用 Radio 列表占用空间大

### 1.2 目标

- 所有重要操作在请求完成前给予明确的视觉反馈，防止误操作
- 输入区域布局合理，支持自适应高度，页面切换时输入内容不丢失
- 消息展示更清晰完整，工具调用过程可追溯，最新内容默认可见
- 创建会话弹窗视觉统一、信息完整、交互高效

### 1.3 成功标准

- 用户无法在同一个操作上连续点击两次（按钮点击后立即 disabled）
- 输入框不需要手动拖拽即可输入多行文本
- 切换页面回来后，输入框内容保持不变（发送后清空）
- 最新一条可展开的消息进入视野时自动展开，无需手动点击
- 工具调用按 kind（edit / execute）和 status（in_progress / completed）差异化展示内容，非聚合状态时间线
- 创建会话的操作路径减少纵向滚动

## 用户分析

### 2.1 目标用户

所有使用 Agent Web 进行 AI 编程的用户。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点 |
|------|----------|------|------|
| 关闭/删除运行中的会话 | 开发者 | 快速清理不需要的会话 | 点击后界面无反应，不确定是否已触发，可能重复点击 |
| 在会话中输入长段代码/问题 | 开发者 | 连贯地输入多行内容 | 输入框固定高度，需要手动调整，输入时无法看到上下文 |
| 在页面间切换后继续编辑输入 | 开发者 | 切换页面后还能看到未发送的内容 | 切换页面后输入内容丢失 |
| 查看 AI 执行工具调用过程 | 开发者 | 了解 AI 正在做什么、执行状态 | 只看得到完成状态，过程中不知道进展 |
| 阅读 AI 的思考过程 | 开发者 | 理解 AI 的推理逻辑 | 每次都需要手动点击展开，新内容不会自动展开 |
| 回顾多条用户消息 | 开发者 | 区分自己不同时间输入的内容 | 连发的多条消息被合并成一条，无法区分 |
| 创建新会话选择工作目录 | 开发者 | 快速从列表中选择目标目录 | Radio 列表在目录多时占空间大，需要大量滚动 |

## 功能需求

### 3.1 功能概述

优化 Agent Web 用户界面的交互细节，覆盖操作反馈、输入体验、消息展示和会话创建四个核心流程，提升日常使用效率。

### 3.2 功能列表

#### 功能点 1: 操作加载状态反馈

- **描述**: 所有调用后端接口的操作按钮在请求未返回时显示加载状态，按钮置灰并显示加载动画，防止重复点击。完整的后端交互点清单见附录。
- **用户价值**: 用户能明确感知操作正在进行，避免焦虑和误操作
- **验收标准**:
  - [ ] 点击"Close"按钮后按钮显示旋转动画且不可再点击
  - [ ] 点击"Delete"按钮后按钮显示旋转动画且不可再点击
  - [ ] 侧边栏切换 Session 时显示加载中状态
  - [ ] 点击"Continue"恢复会话时按钮显示加载状态
  - [ ] 操作完成后按钮恢复正常状态

#### 功能点 2: 输入框布局与自适应高度

- **描述**: 
  - 将模式选择（Mode）和模型选择（Model）独立成一行，消息输入框独占另一行
  - 输入框根据内容自动增高，最高 5rem（约 80px），超出后内部滚动
  - 按 sessionId 将未发送的输入内容存入 localStorage，发送成功后清空；切换页面后自动恢复
- **用户价值**: 输入区域更宽敞、整洁，输入长内容时不需要手动调整输入框高度，切换页面不丢失输入
- **验收标准**:
  - [ ] Mode 和 Model 选择显示在输入框上方单独一行
  - [ ] 文本输入区占满整行宽度
  - [ ] 输入单行文本时高度为默认单行高度
  - [ ] 输入多行文本时高度随内容增加，最高不超过 5rem
  - [ ] 超过 5rem 后内容在输入框内滚动
  - [ ] 发送消息后输入框重置为单行高度
  - [ ] 打开 Session 页面时自动恢复该 session 的上次输入内容
  - [ ] 发送成功后清除 localStorage 中对应的输入内容

#### 功能点 3: 工具调用差异化展示

- **描述**: 
  - 工具调用只展示最新一条（而非聚合所有历史状态），根据 `$.kind` 和 `$.status` 决定展示内容
  - `$.kind === 'edit'` 且 `$.status === 'in_progress'`：
    - 展示 `$.locations` 和 `$.rawInput`（如有）
    - `$.locations` 展示为修改列表（文件路径 + 行号）
    - `$.rawInput.filePath` 显示当前修改文件，`$.rawInput.oldString` / `newString` 展示为左右对比的 diff 视图
  - `$.kind === 'edit'` 且 `$.status === 'completed'`：
    - 展示数组 `$.content[]`
    - `type === 'content'` 的项渲染文本内容（与 AI 消息/用户消息渲染方式相同）
    - `type === 'diff'` 的项展示左右文件差异（基于 `oldText` / `newText`）
  - `$.kind === 'execute'`（命令行执行）且 `$.status === 'in_progress'`：
    - 展示 `$.rawInput`：工作路径（workDir）、标题（description）、命令（command）、超时（timeout）
  - `$.kind === 'execute'` 且 `$.status === 'completed'`：
    - 使用命令行展示组件展示 `$.rawOutput.output`（可能包含特殊转义/控制字符）
  - 卡片外部（折叠态摘要）显示 `kind + status` 简要信息
- **用户价值**: 用户可以清晰看到 AI 正在执行的操作内容（修改文件的具体 diff、执行的命令及输出），而非仅看状态流转
- **验收标准**:
  - [ ] edit in_progress 时显示修改文件列表和左右 diff 对比
  - [ ] edit completed 时显示修改结果内容（content 块和 diff 块）
  - [ ] execute in_progress 时显示工作路径、命令、超时信息
  - [ ] execute completed 时显示命令输出（含控制字符处理）
  - [ ] 卡片折叠态摘要显示 `kind + status`

#### 功能点 4: 最后一条可展开消息自动展开

- **描述**: 在消息列表中，最后一条可折叠的消息（如思考过程、工具调用等）默认展开显示内容；当新的消息到达时，只折叠上一条被自动展开的消息，展开最新一条。消息量较大时，不对所有消息进行折叠操作，只处理上一次展开的那条。
- **用户价值**: 用户无需手动操作即可查看最新内容，保持阅读连贯性，且不会影响已手动折叠的历史消息
- **验收标准**:
  - [ ] 页面加载后，最后一条可展开消息默认展开
  - [ ] 新的可展开消息到达时，只折叠上一次被自动展开的那条消息，然后展开新消息
  - [ ] 用户手动折叠或展开的消息不受自动行为影响
  - [ ] 对于多条消息拼成的一条（如连续的 thinking chunk），整条视为一个整体

#### 功能点 5: 用户消息独立展示（两个 BUG 修复）

- **描述**: 此功能点修复两个不同的 BUG：
  - **BUG 1**：AI 返回的消息（类型为 `agent_message_chunk`）错误的与用户消息（类型为 `user_message_chunk`）合并在一起，导致 AI 回复和用户输入显示在同一个气泡中
  - **BUG 2**：用户连续发送的两条消息被错误的合并为一条，导致无法区分不同时间输入的内容
- **用户价值**: 在回顾对话时可以清楚区分每次输入的内容，消息展示符合正常对话逻辑
- **验收标准**:
  - [ ] BUG 1 修复：AI 返回的消息不会与用户消息合并在同一个气泡中
  - [ ] BUG 2 修复：用户连续发送两条消息，显示为两个独立的气泡

#### 功能点 6: 创建会话弹窗视觉优化

- **描述**: 
  - 工作目录选择从 Radio 列表改为下拉选框，选项保留名称和路径两行信息
  - ACP Server 选择从 Radio 列表改为下拉选框，选项保留类型和版本两行信息
  - Worktree 设置中「启用 Git Worktree 隔离工作目录」复选框文字当前在某些主题下与背景色相同导致不可见，改为显式文字颜色
  - 分支名称前缀（工作空间名称）当前和分支后缀在同一行，当工作空间名称较长时溢出；改为前缀独占一行，后缀在下一行
- **用户价值**: 创建会话流程体验更一致，信息清晰可读，不受长名称影响
- **验收标准**:
  - [ ] 工作目录使用下拉选框，选项保留名称和路径两行展示
  - [ ] ACP Server 使用下拉选框，选项保留类型和版本两行展示
  - [ ] 「启用 Git Worktree 隔离工作目录」文字颜色始终可见
  - [ ] 分支名称前缀独占一行，后缀在下一行
  - [ ] 当前 auto-select 逻辑保留（默认选中第一个）

### 3.3 用户操作流程

```mermaid
flowchart LR
    subgraph 操作反馈
        A[点击 Close/Delete] --> B[按钮显示加载动画]
        B --> C[接口返回]
        C --> D[恢复正常/跳转]
    end

    subgraph 消息展示
        E[收到新消息] --> F{可展开?}
        F -->|是| G[折叠上一次自动展开的消息]
        G --> H[展开新消息]
        F -->|否| I[正常展示]
    end

    subgraph 创建会话
        J[选择控制器] --> K[下拉选择 ACP Server]
        K --> L[下拉选择工作目录]
        L --> M{是 Git 仓库?}
        M -->|是| N[可选启用 Worktree]
        N --> O[前缀独占一行 + 后缀输入框]
        M -->|否| P[直接创建]
    end
```

### 3.4 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| 会话详情页 Header | 顶部操作栏 | Close/Delete/Continue 按钮（带 loading 状态） |
| 会话详情页输入区 | 底部输入区域 | Mode 选择器、Model 选择器（第一行）；自适应 textarea + 发送按钮（第二行）；localStorage 持久化 |
| 会话详情页消息列表 | 中间消息展示 | 可折叠卡片（只折叠上一次展开的卡片，展开最新一条）、工具调用差异化展示（edit diff / execute 终端输出）、独立用户消息 |
| 新建会话弹窗 | 模态弹窗 | 控制器选择、ACP Server 下拉、工作目录下拉、Worktree 设置（前缀独占一行） |

### 3.5 异常与边界情况

| 情况 | 预期行为 |
|------|---------|
| 快速连续点击 Close | 第一次点击后按钮 disabled，后续点击无效 |
| 输入框输入极长文本（超过 5rem） | 输入框高度固定 5rem，内容在内部滚动 |
| 多条工具调用连续返回 | 每个工具调用独立展示最新一条的内容（edit diff 或 execute 输出） |
| 同时收到多条新消息 | 只展开最后一条可展开消息，折叠上一次自动展开的那条 |
| 工作目录下拉选项为空 | 显示"暂无工作区，请先在设置中管理工作区"提示 |
| ACP Server 下拉加载中 | 显示加载状态提示 |
| 同时打开多个 Session 页面 | 每个 Session 的输入内容独立存储，互不干扰 |
